Architectural & Design Principles

    Separation of Concerns (SoC): Clearly divide the system into distinct layers, such as the User Interface, Game Logic, and Data Communication.

    Single Responsibility Principle (SRP): Ensure every class and method has exactly one well-defined task.

    Low Coupling & High Cohesion: Minimize dependencies between components (e.g., AI logic vs. Server communication) and ensure internal logic within a class is closely related.

Information Hiding: Hide internal implementation details and data using private modifiers; expose functionality only through defined interfaces.

Composition over Inheritance: Use object composition and interfaces to achieve flexibility rather than deep inheritance trees.

Model-View-Controller (MVC): Decouple the game state (Model) from the graphical output (View) and the input processing (Controller).

Dependency Injection (DI): Pass dependencies (like a Network Client) into a class via constructors or setters rather than instantiating them internally to increase testability.

Inversion of Control (IoC): Utilize frameworks where the flow of control is dictated by the framework rather than the custom code.

Implementation & Clean Code

    Avoid null Entirely: Do not use null to represent missing data or errors; instead, use Optional, default values, or empty collections (e.g., Collections.emptyList()).

Command-Query Separation (CQS): A method should either perform an action (Command) or return data (Query), but never both simultaneously.

No Magic Numbers: Replace literals (e.g., map sizes or movement costs) with named final constants or descriptive methods.

Meaningful Naming: Use nouns for classes and verbs for methods; names must accurately and completely reflect the behavior.

Standardized Coding Conventions: Follow specific language styles (e.g., CamelCase for Java) and consistent formatting (indentation, line lengths).

Explicit Method Scopes: Use the most restrictive access modifier possible (prefer private over public).

Small Method Parameters: Pass only the minimum amount of data required; avoid passing complex objects if only one field is needed.

Advanced/General Industry Best Practices

    KISS (Keep It Simple, Stupid): Avoid over-engineering; choose the simplest solution that fulfills the requirement.

    DRY (Don't Repeat Yourself): Abstract duplicate logic into reusable methods or components.

    YAGNI (You Ain't Gonna Need It): Do not implement functionality until it is actually required.

    Fail-Fast Principle: Validate inputs and states immediately; throw exceptions as soon as an unexpected state is detected.

    Immutability: Use immutable objects (e.g., record in Java) for data transfer objects (DTOs) like map coordinates or player stats to prevent side effects.
